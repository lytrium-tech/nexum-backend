# Nexum Backend V1.7 - Cross Currency Test Tech Debt

## Context
During the implementation of the `amount_due` and `source_account_id` fixes for the V1.7 Obligations and Payments endpoints, the test `test_pay_specific_period_cross_currency_success` failed with `{'detail': 'fx_quote_not_found'}`, resulting in a `404` status code instead of the expected `201`.

## Root Cause
This is purely a testing/mocking issue, not a runtime logic issue.
The endpoint `POST /api/v1.7/obligations/{obligation_id}/periods/{period_id}/payments` looks up an `FXQuote` when `quote_id` is passed. In the test, we mock `session.execute()` using `side_effect=mock_execute_side_effect`. 
The mock function checks `if "fx_quote" in stmt_str` to return `mock_quote`. However, the mock either fails to match the SQL query generated by SQLAlchemy `select(FXQuote).where(...)`, or the nested structure of `MagicMock(scalars=MagicMock(first=...))` fails to resolve correctly to the `mock_quote` object when evaluated asynchronously inside `service_v17.py`.

## Impact
Zero runtime impact. The production logic correctly queries `FXQuote` using the standard `select()` pattern.

## Next Steps
- Update `tests/unit/test_obligations_v17_api.py::test_pay_specific_period_cross_currency_success` to properly mock the `session.execute` response for `FXQuote`.
- Ensure the mock's `user_id` type (`str` vs `UUID`) correctly aligns with the assertions in the service (`str(quote.user_id) != user_id`).
